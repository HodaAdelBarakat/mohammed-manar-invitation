# Mohammed & Manar Wedding Invitation

A mobile-first wedding invitation website for GitHub Pages.

## Included
- `index.html`, `style.css`, `script.js`
- Photos provided for the invitation
- Music file provided in this conversation (`assets/wedding-song.m4a`)
- Countdown to 13 November 2026, 6:00 PM Egypt time
- Guestbook UI, ready to connect to Supabase

## Important about the guestbook
GitHub Pages only hosts static files. To store messages and show them to all visitors, connect a database such as Supabase.

### Supabase setup (do this before public launch)
1. Create a project at https://supabase.com/
2. In the SQL Editor, run:

```sql
create table public.wedding_messages (
  id bigint generated by default as identity primary key,
  name text not null check (char_length(name) between 1 and 60),
  message text not null check (char_length(message) between 1 and 500),
  created_at timestamptz not null default now()
);

alter table public.wedding_messages enable row level security;

create policy "Anyone can read wedding messages"
on public.wedding_messages for select
to anon
using (true);

create policy "Anyone can send a wedding message"
on public.wedding_messages for insert
to anon
with check (
  char_length(trim(name)) between 1 and 60
  and char_length(trim(message)) between 1 and 500
);
```

3. In Supabase Project Settings → API, copy the Project URL and the `anon` / publishable key.
4. Open `config.js` and fill in `supabaseUrl` and `supabaseAnonKey`.
   - Never use the `service_role` key in a public website.
5. To help reduce spam, add a CAPTCHA/anti-spam service before launching publicly. The basic policies above validate lengths but do not prevent spam.

## Publish with GitHub Pages
1. Create a new public repository on GitHub, e.g. `mohammed-manar-invitation`.
2. Upload all files and folders from this project (keep `assets/` and its files).
3. Open the repository Settings → Pages.
4. Under Build and deployment, choose Deploy from a branch, select `main` and `/(root)`, then Save.
5. Wait for the published URL shown in the Pages section.

## Notes
- Audio starts only after the visitor taps the play button because browsers commonly block autoplay with sound.
- The uploaded music was an `.m4a` file, so it is included in that format.
- Confirm the venue address and date/time before sharing the final invitation.
